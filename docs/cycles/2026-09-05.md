## 実際の投稿処理について(重要)

`docs/agents/promoter.md` の記載どおり、このCoworkサンドボックス環境からは `api.pinterest.com` / `api.twitter.com` への通信がブロックされているため、実際の投稿は本サンドボックスでは行えない設計になっている(dry-runでの検証まで)。本来の運用フローは「manifestをgit commit → git push → GitHub Actions(`run-promotion.yml`)が実際の投稿を行う」だが、今回のサイクルでは以下の理由でgit操作が完了できなかった:

- リポジトリの `.git/index.lock` および `.git/ORIG_HEAD.lock` が、iCloud同期フォルダの権限制約により削除できず(`Operation not permitted`)、`git add` / `git pull` が失敗した
- ローカルブランチは現在 `origin/main` より10コミット遅れており(fast-forward可能)、この同期も完了できていない

**そのため、今回生成したピン画像・manifest・記事は `website/` フォルダ内に保存済みだが、GitHubへのpush、およびそれをトリガーとした実際のPinterest/X投稿は行われていない。**

対応が必要な場合、ユーザーのローカル環境(Finder/ターミナル等、フルアクセス権限を持つ環境)から以下を実行することを推奨:
```
cd .../website
rm -f .git/index.lock .git/ORIG_HEAD.lock
git pull
git add src/posts/red-light-therapy-vs-massage-gun.md docs/cycles/cycle_manifest_2026-09-05.json docs/cycles/_generated_pin_*.png
git commit -m "cycle: red light therapy vs massage gun article + promotion manifest (2026-09-05)"
git push
```
push後、GitHub Actionsの`run-promotion.yml`が自動的に実際の投稿を行う(Pinterestは認証情報未設定のためスキップ、Xは認証情報設定済みのため投稿される見込み)。

### 認証情報の現状(`.env`確認結果)
- Pinterest: `PINTEREST_ACCESS_TOKEN` / `PINTEREST_DEFAULT_BOARD_ID` ともに未設定 → Pinterest投稿は認証情報未設定のためスキップされる設計
- X (Twitter): API Key/Secret/Access Token一式が設定済み → git push後にGitHub Actionsが実行されれば投稿される可能性が高い(ただし本サイクルではpushが完了していないため、投稿は発生していない)
