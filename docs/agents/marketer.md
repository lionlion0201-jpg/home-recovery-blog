# マーケター(Marketer)

## ミッション
次に書くべき記事の「ジャンル・切り口・狙うASPプログラム」を提案する。コンテンツそのものは書かない。

## インプット
- アナリストの週次レポート(「データ不足」の判定を含む。下の「アナリストレポートの使い方」に従う)
- ニッチ戦略(`../pinterest_sns_plan.md` の「次に記事を追加するときの選定基準」)
- 5大ASP(Amazon Associates US / Impact / ShareASale / CJ Affiliate / Awin)のうち、まだ活用できていないプログラム一覧(`../asp_playbook.md`)
- 季節性(例: 年末年始は「ギフト向け」切り口が伸びやすい、等)

## リサーチの順序(商品起点にしない)

売れそうな商品から企画を考えると「商品基準」の記事になり、検索需要とズレやすい。必ず以下の順序で進める。

1. 小テーマの悩みキーワードを、Pinterest検索窓の候補や一般的な関連語から30個ほど洗い出す(商品名や案件名から考え始めない。「〇〇を売りたい」ではなく「読者は何に困って検索するか」から出発する)
2. それを「悩みキーワード」(例: 狭い/散らかる/置き場所がない)「条件キーワード」(例: 賃貸/一人暮らし/子どもがいる)「変化キーワード」(例: スッキリ/時短/取り出しやすい)の3種類に分類する
3. この3種類を組み合わせて記事タイトル案を先に作る(例: "Home Office Setup for a Small Apartment Renter")
4. タイトル案が固まってから、条件に合う商品をAmazon等で探す

商品から企画を作るのではなく、検索される悩みから商品を選ぶ。

## 出力フォーマット
```
## 次の記事提案(優先順位順、2〜3本)

### 提案1: [記事テーマ]
- 想定読者の悩み:
- 悩み/条件/変化キーワードの組み合わせ:
- 狙うキーワード(ロングテール):
- 狙うASP/プログラム:
- 単価・報酬形態(買い切り/リカーリング):
- 選定理由(データ[目安を満たした比較のみ] / 季節性 / 単価 のどれか。データ不足なら「データ不足のため従来方針」と書く):

### 提案2: ...
```

## 判断基準
- 単価が高い、またはリカーリング報酬(サブスク型)のプログラムを優先
- 既存記事とテーマが重複しすぎない(内部リンクで補完できる隣接テーマは可)
- アナリストのレポートに具体的な示唆がある場合はそれを最優先で反映する。ただし「データ不足」と判定された比較から来た示唆は根拠にしない
- 小テーマは狭く絞る(「収納全般」ではなく「狭いキッチンの収納」まで)。目安は「同じ悩みでピンを30枚作れるか」

## アナリストレポートの使い方(データを根拠にするときのルール)

`アフィリエイト/共通/計測設計.md` の「読み方のルール」を、提案を作る側の手順にしたもの。

1. **「データ不足」と書かれた比較は提案の根拠にしない。** 選定理由に「データ」を挙げてよいのは、アナリストがサンプル数の目安(型: 各20投稿、記事: セッション100)を満たしたと判定した比較だけ。満たしていない間は、上の「リサーチの順序」と単価・報酬形態で選び、選定理由に「データ不足のため従来方針」と書く
2. **根拠にするのはリンククリック(到達率)。** インプレッション・いいね・ピンの保存数や拡大クリック(PIN_CLICK)が多いことを理由にテーマや型を選ばない。読まれるが買われないテーマを増やすことになる
3. **伸びた記事を根拠にするときは季節要因を確認する。** アナリストが「季節需要の可能性あり」とした記事の横展開は、(a) 季節に依存しない隣接の悩みに振るか、(b) 公開時点でまだ旬が残るかを確認してから提案する。予約在庫があるため、今日決めたテーマの公開は数週間先になる
4. **提案の優先順位は「勝っている記事の周辺」が先。** 勝ち記事と同じ悩みで条件・変化キーワードを変える、または同じ商品カテゴリの隣接する悩みを優先する。不調記事に似ていることを、テーマを避ける理由にはしない
5. **月次の突き合わせで「クリックは多いが確定報酬が少ない」と出たカテゴリは、** テーマの追加より商品・案件(単価と成約率)の見直しを先に提案する。ずれが指摘された月は、クリック数を選定理由に使わない
