# 週末公開レビュー(人間によるチェックフロー)

## なぜこれが必要か

共通ルール文書 `rule of foreign affiliate.md` の「各エージェントの境界」にこう書いてある。

> ディレクター: チェックリストに基づく機械的な承認/差し戻し判定まで。**最終的な公開承認は必ず人間が行う**

**2026-09-21まで、USサイトはこれを守っていなかった。** 週次パイプラインが生成した記事をその場でcommit・pushし、記事公開もX投稿も人間の承認を経ずに実行していた。JPサイトは最初から守っていたので、USだけが例外的にルールから外れていた状態だった。

加えて、同日の点検で以下が見つかった。どちらも公開後に発見したもので、承認フローがあれば出る前に止められた。

- `sauna-blanket-vs-home-sauna` のAmazonリンク1本に**アフィリエイトタグが付いていなかった**(クリックされても報酬が発生しない)
- 2本の記事に**医療免責の記述が無かった**(ルール文書は「情報提供であり医療アドバイスではない旨を明記する」と要求している)

## 全体の流れ

```
土 09:00  週次パイプラインが記事3本を生成
          → 下書き(published: false)で保存
          → マニフェストは docs/cycles/pending/ に保留(X投稿は走らない)

週末      python3 scripts/build_review.py
          → docs/review/review.html をブラウザで開く
          → 承認/見送り・公開日・SNS投稿の型を選ぶ
          → 「決定を書き出す」で decisions.json をダウンロード
          → docs/review/ に置く

          python3 scripts/apply_review.py --dry-run   # 確認
          python3 scripts/apply_review.py             # 反映
          → フロントマターを書き換え、publishAt を付与
          → 承認分のマニフェストを docs/cycles/ へ移動

          git add -A && git commit && git push
          → pushをトリガーにX投稿が走る
          → publishAt の日に記事が自動公開される
```

## レビュー画面が自動で見てくれること

人間が毎回目で追う必要はない。これらは `scripts/review_lib.py` が機械的に判定する。

| チェック | 重さ | 背景 |
|---|---|---|
| 内部リンク先の公開日が、その記事より前か | error | リンク先が未公開だと**404になる**。2026-09-19に未公開記事のページ出力を止めた副作用。目視では追えない |
| 医療免責の文言があるか | error | ルール文書の要求。2026-09-21時点で2本が違反していた |
| Amazonタグと `rel="nofollow sponsored"` | error | タグ漏れは報酬の取りこぼしに直結する。実際に1本あった |
| タイトルの重複 | error | |
| 断定表現(guaranteed / cures 等) | warn | ルール文書の「絶対NG表現」 |
| 季節性と公開予定日のずれ | warn | ギフトガイドを1月に出しても意味がない |
| 本文の分量 | warn | |

## 人間が見るべきこと

機械が拾えないのはここ。**レビューの時間はここに使う。**

```
[ ] 紹介している商品が実在し、リンク先の検索結果が妥当か
[ ] 数字・事実関係に明らかな誤りがないか
[ ] 比較の結論が、記事内の根拠から自然に導けているか
[ ] 文章として読めるか(機械翻訳的な不自然さがないか)
[ ] 既存記事と主張が矛盾していないか
```

## 見送る場合

何もしなくてよい。下書きのまま残るので、翌週以降に書き直して再利用できる。
見送った理由は `docs/cycles/` のサイクルログに追記しておくと、次サイクルのアナリストが参照できる。

## 補足

- `apply_review.py` は適用の直前にもう一度チェックを走らせる。レビュー画面を開いてから決定するまでに他の記事の公開日が動いていると、リンクの順序が壊れることがあるため
- error が残っている状態では中断する。`--force` はあるが、原則使わない
- `review.html` と `decisions.json` は `.gitignore` に入れてある。前者はいつでも作り直せる生成物、後者はその回限りの判断結果
